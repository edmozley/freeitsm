## What this release is about

FreeITSM has been in development since February 2026. In that time it has grown into a full service desk, been translated into twenty-four languages besides English, and - much more importantly - been used, questioned and corrected by people running it in the real world. Twenty of you have raised an issue or started a discussion, and a great deal of what is in this release exists because somebody took the time to say what was wrong or what was missing.

So this is 1.0.0, and I am proud of it.

Until now there was only `main`. If something broke after an update there was no "before" to name and nothing to go back to, and "which version are you on?" had no honest answer. From today FreeITSM has version numbers: this release is a fixed point you can name, return to, and read the notes for.

**1.0.0 does not mean finished.** It means the contract is stable - that upgrades from here will tell you what they ask of you, and that a version number means something. Development carries on at exactly the same pace.

If you are interested in the full story of how FreeITSM got here, every one of the 1,432 changes is listed at **[freeitsm.co.uk/updates.php](https://freeitsm.co.uk/updates.php)**, from the first commit in February to this release.

## What is in it

Everything. This is the first tagged release, so rather than a list of changes since last time, here is what you get:

- Tickets, with a self-service portal, email integration, SLAs and a knowledge base
- Assets, software, contracts and a CMDB with dependency mapping
- Change and problem management, plus a war room for major incidents
- Tasks, forms, workflows, a calendar and a learning management system
- Service status pages, morning checks, Watchtower and reporting
- Network and process mapping
- Single sign-on (OIDC), LDAP and Active Directory, and a REST API
- Multi-tenancy, role-based access control, and per-user themes and time zones
- Sixteen modules rebuilt to work properly on a phone, with the rest following
- Twenty-five languages

## Upgrading

If you are already running FreeITSM from `main`, you are on 1.0.0 or close to it. To land exactly here:

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**.
3. Hard-refresh your browser (Ctrl-F5).

You can then confirm it worked: the **System** screen now prints the version, and every **Debug Tools** report is stamped with it on the first line.

**A note on pinning.** This release gives you a version number and a git tag you can check out. It does not yet give you a pinned Docker image - `docker-compose.yml` still builds from source, so `image: edmozley/freeitsm:1.0.0` will not work today. Published, tagged images are the next piece of this work, and they are the part that makes a version genuinely pinnable. I would rather say so than imply otherwise.

## Rollback

Nothing to roll back to - this is the first release. From 1.0.1 onward every set of notes will say plainly whether that release can be reversed, and where it cannot, why.
