## What this release is about

Nothing new to learn and nothing to configure. This is a set of corrections to places where FreeITSM displayed something misleading - a chart with two slices sharing a name, a form answer shown as a **1**, a contract badge that went green precisely when you had labelled it as expiring.

Most of them were found the same way: by going through the product screen by screen with fresh eyes while re-photographing it for the website. None of them broke anything, which is exactly why they had survived - a wrong colour or a missing label does not throw an error, it just quietly misinforms whoever is reading it.

The one substantial change is to **My courses** in the LMS, which now shows how far through each course you are.

## Improvements

- **My courses shows your progress, and can be read as cards.** The learner's own page sat in a narrow column in the middle of the screen, so a handful of assigned courses looked like an empty page. It now uses the full width, and every course carries a progress bar with the words **Lesson 2 of 3** beside it. The words are deliberate: the only position FreeITSM records is which lesson you are on, so a bar on its own would suggest a measured percentage of the material that nothing actually measures. A course nobody has opened says **Not opened yet** rather than showing a misleading nought, and courses uploaded as SCORM packages get no bar at all, because a package keeps its own place in a form that cannot be counted. A **list and cards switch** sits at the top right, the same two icons and the same behaviour as the one in Knowledge, and it remembers which you chose.

- **Naming a new process no longer uses a browser pop-up.** Pressing **+ New** in the Process Mapper opened the browser's own prompt box - the kind that says "localhost says", freezes the page until you answer it and ignores your theme. It was also the one dialogue in the module that always arrived in English, whatever language you were working in. It is now a proper dialogue that matches the rest of the module.

## Fixes

- **A chart could show two slices with the same name.** On the Software dashboard, applications whose publisher was never reported reached FreeITSM in two different shapes - genuinely absent, and present but empty - and the Publisher Distribution chart treated those as two separate publishers while labelling both of them **Unknown**. So a dashboard could carry two identically named wedges of different sizes with no way to tell them apart, and every count was split across the pair. They are now counted as one, and the label reads **Not recorded**, because the application is not unknown and usually neither is its publisher - the inventory simply did not report one. The version charts had the identical fault and are fixed with it.

- **Half the bars on a software chart had no label.** A chart of the twenty most installed applications showed ten names along the bottom, because the charting library's answer to a label that will not fit is to drop it silently rather than shorten it. Ten bars stood there unidentified with nothing to say that a name was missing rather than absent. Names are now shortened to fit and every bar is labelled, with the full name when you point at it. The publisher list beside the doughnut chart no longer spills a single entry into a second column.

- **A yes/no answer on a form showed as a 1.** An approver opening a catalogue request read *"My budget holder has approved this spend: 1"* - you had to know how the answer was stored to read your own inbox, and a **0** was indistinguishable from an unanswered question. Tick boxes now say **Yes** and **No**, including in the ticket raised when a request is approved and in the email the requester receives. Only the single yes/no tick box was affected; the multiple-answer version always listed the options people chose.

- **Setting a contract's status made its badge wrong.** The coloured badge on the contract list answers two different questions - how urgent is this, and where has the paperwork got to - and it was answering both with the status. Any contract that had one was painted green whatever its dates said, so a contract three weeks from its end date, correctly marked with the **Expiring Soon** status FreeITSM ships with, showed a green badge reading "Expiring Soon". The only way to get the amber one was to leave the status blank. The end date now decides the colour and the status decides the label, so a contract that is both "Renewal Pending" and three weeks from expiry looks like both at once.

- **An overdue learner was invisible in dark mode.** On **LMS → Progress**, the row for somebody who has missed their training deadline is tinted to mark it - and that tint was a pale pink designed for a white page, with no dark-theme equivalent. On a dark screen it rendered as a near-white band carrying pale grey text, so the one row you most need to read was the one you could not.

- **The form builder guide described four field types. There are eleven.** Anyone reading it would not have known that Email and Number check what is typed as it is typed, that radio buttons and multiple-choice tick boxes exist alongside the single one, that there is a date and time picker, that a **Lookup** field can pull a real record from elsewhere in FreeITSM into a form, or that section headings can break a long form into parts. The guide had not been revisited as the builder grew.

## Upgrading

1. Pull the new code, or rebuild the Docker image - or, if you pin a version, change it to `ghcr.io/edmozley/freeitsm:1.1.1`.
2. Sign in as an administrator and run **System → Database Verification**.
3. Hard-refresh your browser (Ctrl-F5). Several stylesheets and scripts changed.

Nothing else needs doing by hand. No new environment variables, no permissions to set, no scheduled tasks to create.

## Rollback

Safe - this release does not change the database at all, so you can go back to 1.1.0 by checking out the older tag or changing the pinned image number.
