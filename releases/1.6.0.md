## What this release is about

Two things, and the second one is the reason not to leave this upgrade until next week.

The new feature is **teams**. Until now a ticket could only be given to a named person, which is fine on a small desk and awkward on a bigger one: the first line rarely knows who in Infrastructure handles what. Now a ticket can go to the **team**, sit in their queue, and be picked up by whoever takes it. Team and analyst are separate, independent facts, so nothing you already do changes.

The fix is that **Reply was putting your own support address in the To field**. If you have an auto-reply configured, this was happening on most tickets, most of the time. It has been there since the first release. Details below, including how to check whether it caught you.

This release also closes a security hole in maintainer scripts that could be run by anyone who could reach your FreeITSM over the web.

## Security

**Five scripts in the `scripts/` folder would run when requested over the web, with no sign-in.** That folder sits inside the web root on a normal install, and seven of the twelve scripts there already refused to run from a browser - these five had simply never been given the same check.

The one that matters most rewrites a PHP file that FreeITSM itself then executes, so on an install where the web server can write to the application folder, an anonymous request could have changed code. Two others send data to an external service using a stored key, and would have spent that key on request.

**Affected versions: every release up to and including 1.5.0.** There is nothing to do beyond upgrading - no configuration to change and no keys to rotate unless you have reason to think one was used. If you want to satisfy yourself, request `/scripts/i18n_audit.php` on your own install: after upgrading it returns 403 and runs nothing.

The check is inside PHP rather than in an Apache rule, deliberately, because an `.htaccess` deny is silently ignored by nginx and IIS - a guard that only works on some installs is worse than none, because you stop thinking about it.

## New features

- **Assign a ticket to a team.** A **Team** field sits beside the analyst on the ticket. Team and analyst are independent and both optional: setting one never changes the other, and clearing the analyst leaves the team behind, so a ticket falls back into its queue rather than disappearing when somebody goes on holiday. Everyone in the receiving team gets a notification on the bell panel. You can set the team from the ticket itself, from the right-click menu in the list, across a whole selection at once, or from a workflow that raises a ticket straight into a queue. The ticket folders can be grouped by team as well as by department or analyst, and your choice is remembered. Assigning to a team is routing, not permission - it never changes who can see a ticket. **If your install has no teams, none of this appears**: no picker, no grouping, nothing to switch off. Asked for in [discussion #125](https://github.com/edmozley/freeitsm/discussions/125).

- **Database verification from the command line.** `php scripts/db_verify_cli.php` applies the schema changes that come with new code, which previously needed a browser and an administrator sign-in. That mattered for anything that upgrades unattended - a Docker container coming up on a new tag, a scripted deploy, a machine that updates itself overnight - because none of those can click a button. It shows you what it would change by default and only acts when you add `--apply`, since this is the same process that can drop columns. It refuses to run over the web.

## Fixes

- **Reply put your own support address in the To field.** Clicking **Reply** filled in the address of whichever message was on screen - which is right for a message somebody sent you, and wrong for one you sent, where that address is your own service desk. Because the ticket list shows the newest message, and an emailed ticket gets an auto-reply within seconds, this was happening on the ordinary path rather than in some corner. Anyone who sent such a reply would have had it arrive straight back as a new ticket from themselves.

  **Worth checking:** search your tickets for mail *from* your own support address. Anything you find is a reply that went to the service desk instead of the person waiting for it, and they are still waiting.

  A fresh install never saw this, which is why it survived since February: FreeITSM ships with no email templates at all, so until you set up an auto-reply there is no outgoing message for Reply to get confused by. It was the installs that had been configured most thoroughly that were affected.

  The same mistake was also making the shared-note hint claim a requester could be emailed when they had no address on file. Both now use one shared answer.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification** - or, new in this release, run `php scripts/db_verify_cli.php --apply` from a terminal.
3. Hard-refresh your browser (Ctrl-F5). This release changes the ticket screen's JavaScript, and a cached copy will still put the wrong address in the To field.

Nothing else to do by hand. Teams appear only if you already have teams; if you do not, this release is the security fix and the Reply fix.

## Rollback

Safe - nothing was removed from the database, so you can go back to 1.5.0. The one new column (a team on a ticket) is simply ignored by the older version, and any teams you assigned are still there if you come forward again.
