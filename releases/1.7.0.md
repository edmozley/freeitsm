## What this release is about

This one is about trusting your asset list.

FreeITSM has always recorded when a machine last reported in, and has shown it almost nowhere. The dashboard would tell you that nine machines had gone quiet and then leave you to work out which nine. Now **every asset says when it was first and last seen**, in your own timezone, and turns amber once a machine has gone more than a week without reporting - and the count on the dashboard is a link straight to the list of them.

The inventory agent has also been collecting the **serial number of every drive inside your machines** since its first version, and throwing it away on arrival. That is the number a warranty claim needs when a disk fails and the one an auditor asks for when a machine is disposed of, and nothing else in FreeITSM recorded it. It is kept now. There is nothing to install - your existing agent deployments start reporting drives after the next database verification.

The fix worth reading is that **an agent report which collected nothing was emptying that machine's inventory**. If a Windows call failed on one run, that machine's disks, network cards or full Device Manager list were deleted and not replaced, silently, until the next good run. That has been fixed, and this release also tidies up hand-added equipment that has been wrongly counted as machines that stopped reporting.

## New features

- **First seen and Last seen on every asset.** The **Key info** tab now shows when an asset was first recorded and when it last reported, in your own timezone, with how long ago that was - "20.08.2026 16:29 - 21 days ago". Once a machine has gone more than seven days without reporting, that turns amber. **Last seen** is also a column in the asset table, on by default and sortable, so one click brings the machines that have gone quiet to the top; **First seen** is available in the column picker. Equipment that no agent will ever report - a television, a SIM card - says **Never reported** rather than showing a blank, so a machine that stopped and a machine that never started never look the same. Asked for in [discussion #97](https://github.com/edmozley/freeitsm/discussions/97).

- **Serial numbers for the drives inside a machine.** The **Storage** section of an asset now lists the physical drives beneath the volumes, each with its model, **serial number**, capacity, media type and interface. Your existing agent deployments already collect all of it - the serials start appearing after you run Database Verification and let each machine report once more. Drives are also available over the API at `/api/v1/assets/{id}/physical-disks`.

- **Hide drives you do not want to see.** Windows reports mounted virtual disks as though they were real hardware, so most machines carry a small "Microsoft Virtual Disk" beside their actual drive - one is a curiosity, six hundred is a panel nobody reads. Hover a drive and press **Hide**, and it offers to take the rest with it: *"Also hide the other 49 drives like this, across every asset"*, counted as you decide. You can hide a drive on one machine or across the whole estate, and a **Show hidden** link sits in the Drives header whenever anything is being withheld. Hiding is a display choice only - the drive stays in your database and stays in the API.

## Improvements

- **The dashboard's "not seen" count is now a link.** The Watchtower Assets card told you how many machines had stopped reporting and gave you no way to find out which ones. It opens the asset table filtered to exactly those machines, with a banner saying what you are looking at and a way back to the full list.

- **The asset list header says how many you have.** It used to read "Assets" and then repeat "597 assets" two lines below. It now says **Assets - 597 found** on one line, and **Add**, **Scan** and **Assign tags** are proper buttons rather than small text links.

## Fixes

- **An agent report that collected nothing emptied that machine's inventory.** Each report replaces a machine's disks, network cards and Device Manager list with what the agent just found. If the agent found nothing - a failed Windows call on one run - the old rows were deleted and nothing was put back, with no error anywhere, until the next good report. An empty report is now treated as "I did not find out" rather than "there is nothing there": the existing list is kept, and the reply says which sections were left alone. This also closes the same behaviour being triggered deliberately by anything holding an inventory API key.

- **Hand-added equipment was being counted as machines that had stopped reporting.** Adding an asset by hand - the **Add** button, a spreadsheet import, or the API - recorded it as though something had reported it. Nothing ever reports a television, so once this release put that date on screen your meeting-room screens and SIM cards would have shown amber, and they had been inflating the dashboard's "not seen" count all along. Database Verification corrects existing equipment when you upgrade, and nothing does it again. **No date is lost** - the date you added it is kept, and only the duplicate pretending to be an agent report is removed.

- **A small virtual disk showed as "0.0 GB".** Windows reports these through the same mechanism as real hardware, and rounding a 31 MB device to one decimal place in gigabytes reads as broken rather than as small. Anything under a gigabyte now shows in MB.

- **The last card in an asset's Key info tab sat hard against the bottom of the pane**, which made a finished list look like a list that had been cut off.

- **Database Verification now tells you about row changes, not only schema changes.** Its preview could say which tables it would create and which columns it would drop, and said nothing about a pass that rewrites existing rows. It now names them and counts them before you press the button.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**. This release adds two tables and corrects the "last seen" date on equipment you added by hand - the preview will tell you how many rows that is on your install before you apply it.
3. Hard-refresh your browser (Ctrl-F5).
4. Nothing to do for the inventory agent. The version already deployed on your machines collects drive detail; it starts being stored the next time each machine reports.

## Rollback

Safe - nothing was removed from the database, so you can go back to 1.6.1 and the older code ignores the two new tables. One thing does not reverse itself: the corrected "last seen" dates on hand-added equipment stay corrected, because rolling back the code does not put a duplicated date back. That affects a badge on screen and a dashboard count, not any date you entered.
