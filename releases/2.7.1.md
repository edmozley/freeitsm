## What this release is about

A fix release for anyone who runs FreeITSM behind a reverse proxy that handles HTTPS - nginx, Caddy, Traefik, Cloudflare or a cloud load balancer in front, which is how most production installs are set up. There, **single sign-on could not work at all**: FreeITSM gave your identity provider an `http://` address to return to, and Microsoft Entra, Google and Okta all refuse that. Reported in [#152](https://github.com/edmozley/freeitsm/issues/152), with a diagnosis that was spot on.

**Fixes an issue present in every earlier release.** If you use single sign-on behind a reverse proxy, upgrade. If you are not behind a proxy, nothing changes for you.

## Fixes

- **Single sign-on failed behind a reverse proxy.** Signing in with Microsoft Entra stopped with error **AADSTS50011** (*the redirect URI specified in the request does not match*), and **System → Single Sign-On** showed an `http://` address to register. Both now use `https://`, as does the address your identity provider sends you back to after signing out.

- **Other links said `http://` behind a proxy too.** Password reset emails, self-service verification and reset emails, satisfaction survey links, links in synced calendar events, QR asset labels, and the addresses shown on **System → API** and **System → Webhooks** all now use `https://`.

- **Docker: old `/login.php` links landed on an error page behind a proxy.** So did a folder address typed without its final `/`. These now go to the right `https://` page.

## Improvements

- **A new guide: [Running behind a reverse proxy](https://github.com/edmozley/freeitsm/wiki/Running-Behind-A-Reverse-Proxy).** The one setting to turn on, the header your proxy must send, and how to check it is working - written down in one place for the first time.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**. Nothing changes in the database this time, but it is a good habit.
3. Hard-refresh your browser (Ctrl-F5).

**Behind a reverse proxy?** These fixes only apply when FreeITSM knows the proxy is there. Check that `TRUST_PROXY_HTTPS` is on: `TRUST_PROXY_HTTPS=1` in `docker-compose.yml`, or `define('TRUST_PROXY_HTTPS', true);` in `config.php`. Only turn it on if the proxy is the only way in - the guide above explains why. Then open **System → Single Sign-On** and confirm the address shown starts with `https://`.

## Rollback

Safe - nothing was removed from the database, so you can go back to 2.7.0 with the code alone.
