## What this release is about

A fix release for anyone who runs FreeITSM on **Apache with PHP-FPM**, the usual production setup on Debian and Ubuntu. There, a logo you uploaded showed as a broken image, the self-service portal's logo did the same, and LMS courses would not open. Reported in [#115](https://github.com/edmozley/freeitsm/issues/115) by @mbsouth, with a diagnosis that was spot on.

**Fixes an issue present in every release from 1.0.0 to 3.1.0.** If you run Apache with PHP-FPM, upgrade, and run **System → Database Verification** afterwards. If you run Apache with mod_php (WAMP, XAMPP, most LAMP installs, the official Docker image), nginx or IIS, you were never affected and nothing changes for you.

## Fixes

- **On Apache with PHP-FPM, an uploaded logo showed as a broken image** - in the header, on the sign-in page, and on **System → Branding** the moment you pressed **Save**. The self-service portal's logo did the same, and LMS courses would not play. Opening the image on its own gave *Internal Server Error*. A settings file in each upload folder contained one line that Apache only understands when PHP runs as mod_php; on PHP-FPM, Apache refused everything in that folder instead. The line is gone, and the rule that stops anything in an upload folder from running as a program is still in place on every server.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**. **On Apache with PHP-FPM this step is needed for the fix to be complete**: updating repairs the folders FreeITSM ships, and Database Verification repairs the ones it created itself while running, such as the portal logo's folder. On other servers it may report repaired files too; that is harmless.
3. Hard-refresh your browser (Ctrl-F5).

**Edited an upload folder's `.htaccess` by hand to work around this?** `git pull` may refuse to overwrite it. Put it back first, for example `git checkout -- system/uploads/branding/.htaccess`, then pull. Your edit is no longer needed.

## Rollback

Safe - nothing was changed in the database, so you can go back to 3.1.0 with the code alone.
