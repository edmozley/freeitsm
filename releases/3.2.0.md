## What this release is about

This release is mostly one new module: **Projects**, for running IT projects - an office move, a laptop refresh, a firewall replacement - on the tasks your team already works in. A project has a plan of phases, stages or sprints, a health ring worked out from the work itself, and can be run simply, the PRINCE2-style staged way or the agile way, switching at any time without losing anything. It is joined to the rest of FreeITSM: its equipment, changes, tickets, contracts, budget, the Calendar, Workflows, Report Packs and Watchtower. An optional **AI project manager** briefs you on what needs attention and drafts status reports for you to check and approve. Alongside it come **planned maintenance** on Service Status, an **MCP server** so AI assistants can read FreeITSM, and a **security fix for API keys** on installs with more than one company. Nothing breaks.

## Security

- **An API key could reach companies its analyst could not.** In every release from 1.0.0 to 3.1.2, on an install with more than one company, a REST API key set to *All companies* covered every company, even when the analyst it acts as was limited to some of them - so it could read and create records in companies that analyst could not open. A key now never reaches further than its analyst: *All companies* means all of that analyst's companies, a list of companies is cut down to the ones the analyst can see, and **System → API** refuses to save a key for a company its analyst cannot see. Single-company installs, and keys for analysts who can see every company, are not affected. **After upgrading, check your keys in System → API:** an integration that relied on reaching other companies through a limited analyst will now see less, and should be given a key for an analyst who is meant to see those companies.

## New features

- **Projects**, a new module. A portfolio of projects, each with its own colour, icon, goal, target date and a health ring - On track, At risk or Off track - worked out from its tasks and dates. A plan of phases, stages or sprints you drag tasks between, run as **Simple, Staged or Agile**, and switch method halfway through without losing anything. Project tasks are ordinary tasks, so they show on the Tasks board for the people doing them, with the project's colour and a Project filter.
- **The project manager's tools**, switched on per project: **People** with project roles, **Scope** prioritised Must, Should, Could, Won't, a **RACI** matrix, a **RAID log** with a risk heat map, and **Gates** - a business case, tolerances, and a go or stop decision at the end of each stage. A lesson from the RAID log becomes a draft Knowledge article, and an issue raises a ticket, in one click.
- **Templates.** Start a project already planned - an office move, a laptop refresh, a mail migration, a Windows 11 rollout or a service desk improvement come built in - or save any project that went well as a template for next time.
- **Asset targets.** Count a project's progress straight from Assets - "312 of 480 laptops replaced" - with a burn-up line, and let a rollout that slips move the health ring.
- **Projects joined to everything else.** Link a project to equipment, changes, tickets, contracts, CMDB items and knowledge articles, and each of those shows the projects it belongs to. A person's page in People lists their projects, their role and what they are accountable for. Global search and Ctrl+K find projects too.
- **A budget.** Planned against actual, with budget lines, contracts, cost centres and the time logged on the project's tasks, priced at hourly rates that each apply from a date - so a new rate never re-prices the past. A project keeps its currency, amounts in different currencies are never added together, and a cost tolerance turns an overspending project Off track.
- **Going live safely.** A stage gate warns about linked changes not yet approved, a jump in tickets linked to a project after go-live turns it amber, and a project can announce its disruption - "Move day: phones down Saturday" - on Service Status.
- **Projects everywhere you look.** Target dates and stage ends appear on the shared **Calendar** and move when the plan does. The project manager's notification bell rings when a project changes health, goes beyond a tolerance or has a stage ending soon, and the same moments are **Workflow** triggers - a project going red can post to Teams. **Report Packs** have Projects blocks for the board pack, and **Watchtower** has a Projects card.
- **An AI project manager**, optional. With an AI provider set up in **Projects → Settings → AI** (Anthropic, OpenAI, Azure OpenAI or OpenRouter, with your own key), a project's Overview offers a **Briefing** on what needs attention this week, and its **Reports** tab drafts highlight, exception and checkpoint reports. The AI only proposes: a report is a draft until the project manager approves it, it only sees what the person asking can see, and nothing is sent to the provider until someone presses Brief me or Draft. You can also write reports yourself without AI.
- **Planned maintenance on Service Status.** Announce maintenance ahead of time with its start, end and the services affected. It shows as Upcoming straight away, becomes an incident on those services when it starts and is resolved when it ends, by itself.
- **An MCP server** for AI assistants. Connect Claude Code, Claude Desktop or any client that speaks the Model Context Protocol, and ask it things like "which projects are off track, and why?" or "is the VPN down?". It is read-only, and sees exactly what the analyst behind its API key may see. **System → API → Connect an AI assistant**.
- **Projects in the REST API**: projects, stages, gates, scope, RAID and budget.

## Improvements

- **Projects works on a phone**, with the portfolio, the plan and the project tools laid out for a small screen.
- **A notification that gathers several events shows the newest one's title**, rather than the first one's.
- **The demo data** includes three projects, so you can try the module before starting your own.
- **The help pages, the wiki and Feature Bingo** cover everything in this release.

## Fixes

- **The API documentation said a deleted record's id came back as text.** It has always been a number; the documentation now says so.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**. It creates the tables for Projects, project reports and planned maintenance.
3. Hard-refresh your browser (Ctrl-F5).

**Who sees Projects:** anyone who can open every module sees it straight away. Anyone whose modules are limited needs Projects added to theirs.

**New permissions**, under **System → Roles**: one for each tab of **Projects → Settings** - General, Health, Roles, RAID, Budget, AI and Templates - with **Manage Projects** covering them all. Administrators have them already. The Budget and AI tabs have their own because they hold pay rates and an API key. API keys have two new permissions: **Projects** and **MCP server**.

**Scheduled tasks:** nothing new to schedule. If you already run `php cron/workflow_scheduled.php`, it now also looks after project alerts and planned maintenance. Without it, they are picked up when someone opens the Projects portfolio or Service Status.

The new screens in this release are in English only for now, and the other languages will follow.

## Rollback

Safe - this release only adds to the database, so you can go back to 3.1.2. Going back also brings back the API key issue described under Security.
