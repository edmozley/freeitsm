## What this release is about

3.2.0 introduced Projects; this release fills in what a project manager expects to find in it. Plans get a proper **Timeline** with milestones, dependencies and the critical path; you can see **who has room** in the weeks ahead; work can be given to **outside contractors**; and staged projects get **change control**, **benefits** and **gate checklists**. You can now **talk to an AI project assistant** about a project - it coaches a blank one into shape, keeps a running one on track and proposes changes you apply with one click. For newcomers there is a **Toolbox** that adds tools as a project grows, and a **How it fits together** page that shows how all the parts connect. Nothing breaks, and nothing new is switched on that changes what your team sees until they use it.

## New features

- **A Timeline.** Each project's plan as a Gantt chart - stages as bands, tasks as bars, milestones as diamonds - that you drag to reschedule. **Milestones** (move day, go-live, sign-off) show on the portfolio and the Calendar, and one that is missed turns the project amber and tells its manager.
- **Dependencies and the critical path.** A task can wait for another to finish, with a gap in days. The Timeline draws the arrows, shows in red where the plan cannot be true as written, and highlights the chain of tasks that decides the finish date.
- **Ask AI - a project assistant you can talk to.** **Ask AI** on a project opens a conversation with an AI project manager. On a project with little more than a name it asks what the project is about and when it should finish, then proposes a whole set-up - goal, dates, stages, tasks, milestones and likely risks. On a running project it points out what is overdue, at risk or waiting for a decision. It never changes anything itself: each suggestion comes with **Apply** and **Dismiss**, and Apply makes the change as you, with your permissions. It remembers your conversation, and catches you up when you come back. It uses the AI provider in **Projects → Settings → AI**.
- **Contractors.** A task can be given to a supplier from Contracts, and a person there, while somebody on your team owns it and chases them. The firm shows on the plan and the Tasks board (with a Contractor filter), can be added to a project's team, and its page in People lists every task it has. Optionally - off unless you turn it on in **Projects → Settings → General** - the contractor is emailed when they are given a task, before it is due and if it is missed.
- **Estimates and Capacity.** Give a task an estimate in hours and see it against the time logged. A **Capacity** page shows each person's load in the weeks ahead - project work plus service desk shifts against the hours they work - so you can see who is over-committed before it happens. Contractor work is listed separately rather than counted against anyone.
- **The charts a project manager asks for.** A burn-up and a burndown, progress by stage, a cumulative flow diagram, a task status breakdown, and **earned value** (planned value, earned value, actual cost, CPI and SPI). On the portfolio, a **Roadmap** of every project across the calendar, a **Charts** view across projects, a **priority** for each project and sorting by it.
- **Budget over time and a forecast.** Budget lines get dates, so spend is drawn month by month, and the forecast shows what the project will cost in the end - estimates still to come included. The overspend tolerance can watch the forecast rather than waiting for the money to be spent.
- **Change control** for staged projects. Take baselines of the agreed plan and see how far it has drifted; raise change requests that are approved or rejected before the plan moves, with approving able to move the target date and add the cost to the budget.
- **Proposals and approval.** Any form can propose a project - why, the estimated cost, the expected benefit - and proposals can wait for an approver before they start.
- **Benefits.** Track what a project is meant to deliver, measured from a baseline towards a target, with review reminders that carry on after the project closes. The AI can draft a closure report.
- **Gates with checklists, and documents on projects.** Each stage gate can carry a checklist - documents, named sign-offs, approved changes, and a starter list for go-live - and every project has a **Documents** tab.
- **A fuller RAID log.** Dependencies on other teams or suppliers, a decision log (who decided, when and why), escalation of any entry to the sponsor, and follow-up actions that become tasks on the project. The RAID log and the portfolio export to **Excel or CSV**.
- **Stakeholders and confidential work.** A power / interest **stakeholder map** with a communications plan on the People tab, and **members-only** projects that only their team can see - for HR, security or anything confidential.
- **Reminders that chase for you.** Project managers get a weekly digest of overdue tasks; anything waiting too long for a decision nudges whoever has to make it; reports can draft themselves each week, fortnight or month; and an approved report can be emailed to the project's people.
- **For beginners: the Toolbox and How it fits together.** A new Simple project starts with very little, and the **Toolbox** on its Overview offers the other tools - what each is for and when you would want it - as the project grows. **How it fits together** (from Projects → Help) is an interactive map of every part of a project and what feeds what, with a step-by-step walk through an office move.
- **More joined up.** Problems can be linked to projects; templates carry dependencies, gate checklists and benefits; and in the War Room, **Warbot** answers questions about projects - which are off track, what is coming up.

## Improvements

- **Much larger demo data.** **System → Demo data → Tasks and Projects** now brings nine projects covering every way of running one and every feature in this release - including one whose cabling is done by a contractor.
- **The AI briefings and reports know more** - dependencies and clashes, gate checklists, the stakeholder map, benefits, earned value and contractors.
- **The REST API** returns each task's estimate and contractor, and accepts both. These are additions only.
- **The help, the wiki and Feature Bingo** cover everything in this release.

## Fixes

- **The AI briefing never mentioned a project's budget**, nor its priority or currency. It does now.
- **An approved report still offered Approve** and the editing buttons.
- **Warbot could not use Azure OpenAI** for its questions - it sent them to the wrong address.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**. It adds the tables and columns for milestones, dependencies, change control, benefits, gate checklists, the AI assistant and contractors.
3. Hard-refresh your browser (Ctrl-F5) - this release updates cached JavaScript and styles.

**Nothing to do by hand.** There are no new permissions and nothing new to schedule; if you run `php cron/workflow_scheduled.php`, it now also sends the project reminders. Every new setting starts with today's behaviour - contractor emails are off, for example - so the upgrade changes nothing your team sees until they use something new.

The new screens in this release are in English only for now, and the other languages will follow.

## Rollback

Safe - this release only adds to the database, so you can go back to 3.2.0.
