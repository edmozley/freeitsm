## What this release is about

This release fixes a security problem in LDAP sign-in and in the LDAP, CardDAV and Entra imports, so if you use any of them, upgrade. It also lets a small service desk simplify its forms: hide the Department field or fill it in automatically, hide the contractor fields on tasks, fold away empty work sections, and ask the portal's questions in the main New ticket form. Internal domains can now check their DNS records and a health page, not only their certificates. Asset labels print cleanly on tape and roll printers.

## Security

- **A directory account could be matched to somebody else's record when an email address or sign-in name was reused.** When an organisation gave a leaver's email address to a new person, the new person's first LDAP sign-in could land in the old person's record - for a requester, with the old person's tickets; for an analyst, with that analyst's access. The LDAP, CardDAV and Entra imports could likewise update the wrong person, and CardDAV could then write changes back to the wrong contact. Sign-in now refuses an account already linked to a different directory identity, and the imports report it as a conflict for an administrator instead of changing anybody. It needed an account in your own directory carrying the reused address, so it was not open to the internet. Affects every version up to 4.8.0 that uses LDAP sign-in or a directory import (CardDAV from 1.8.0). Reported privately by vsc55, with tests - thank you.

## New features

- **Hide the Department field, or fill it in for you.** Under **Tickets → Settings → Custom fields → Department field**, for the whole install or per company, hide Department where you do not use departments, and choose the department new tickets start in - on every channel, from New ticket and the portal to email, chat and the REST API. Hiding only removes the field from the screen: tickets keep their department, and folders, workflows and SLA rules still use it. FreeITSM stops you hiding it while Mandatory fields requires it, or retiring a department that is somebody's default. Asked for by Dr4inder.
- **Hide the contractor fields on tasks.** **Tasks → Settings → Involved** can hide Contractor and Contact there from the task screen, for the install or per company. A task that already has a contractor still shows it, read-only.
- **Fold away empty work sections.** A new preference, **System → Preferences → Empty work sections on a task**, shrinks empty Checklist, Forms and Follow-ups sections to a heading such as *Forms (0)* that opens with a click. A section that cannot load now says so, with **Retry**, instead of disappearing.
- **Portal questions in the main form.** **Tickets → Settings → Custom fields → Where the portal asks these questions** can put the custom field questions on the portal's New ticket page between the subject and the description, two to a row, instead of in the side panel. The side panel stays the default.
- **Expected DNS records on internal domains.** An internal domain's **Health** tab can list the records a name should hold - A, AAAA, CNAME, NS or SOA - with the values you expect if you know them. A missing record, or different values, is reported as a problem on every check.
- **Check a page, not only a certificate.** An internal HTTPS endpoint can also ask for a page such as `/health` and say which status codes are healthy. It is asked only once the certificate passes, and a redirect is reported as the answer, never followed.
- **Internal monitoring in the REST API.** Endpoints, expected records and trust profiles can be managed through the API, with a new **domains.internal** permission on the key. The key's analyst must also hold **Internal monitoring**.
- **Black-only label printers.** Each label design has a **Black-only printer** setting - on for tape and roll sizes - that prints all text and lines in solid black and the logo in pure black and white, so nothing comes out as dots. Raised by zemega.
- **Your usual company for new tickets.** In the all-companies view, **System → Preferences → My company for new tickets** picks a company for you on New ticket. You can still change it.

## Improvements

- **New ticket in the all-companies view follows the company you choose** - the mailbox list and the custom field questions as well as the ticket types.
- **Change Management says "Linked tickets".** Any kind of ticket can be linked to a change, so the section, buttons and messages now say tickets rather than incidents, in every language, and each linked ticket shows its type - Incident, Service Request and so on. Asked for by Dr4inder.
- **Field names on labels are readable.** They print in black and larger, instead of small and grey.

## Fixes

- **Reply was addressed to the assigned analyst instead of the requester** after somebody else assigned the ticket to them. The "this ticket is now yours" email was being saved into the conversation; it now goes to the ticket's history, and Reply ignores older ones. Reported by duongtuanan.
- **A new ticket sent from the all-companies view with no company was filed under the active company,** if the form's own check was bypassed. It is now refused, unless you can reach only one company.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**.
3. Hard-refresh your browser (Ctrl-F5).

If you use LDAP sign-in or a directory import, look at the **History** of your next import run: any person reported as a conflict is a record two directory accounts were claiming, and is waiting for you to decide who it belongs to.

## Rollback

Safe - nothing was removed from the database, so you can go back to 4.8.0, though that brings the security problem back.
