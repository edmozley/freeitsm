## What this release is about

**Nothing breaks.** 5.0.0 is a milestone number, not a breaking change: every setting, workflow and screen you use today works exactly as it did, every new behaviour that changes anything is off until you switch it on, and you can go back to 4.12.0 if you need to.

The number says how much has arrived. Every module now has a **help assistant** that answers questions from FreeITSM's own help, and can write the answer in your words if you give it an AI key. Screens now **keep up by themselves** - the ticket list, the open ticket, the tasks board and the bell follow what everybody else is doing, without ever throwing away what you are typing. You can **watch a ticket** you do not own, put **forms on a ticket**, and build **workflows that route tickets by category** or act on tasks. And FreeITSM now speaks **Greek**, with Polish and Indonesian complete.

## New features

- **Help assistant, in every module.** A help icon in each module's header searches the help as you type and opens the answer in place. With an embedding model (System → Help assistant) it matches by meaning too, so "how do I stop getting emails" finds the notification settings; with a chat AI it writes a short answer from the help alone and says where to find the setting, never inventing a menu. Questions it could not answer are listed for you, so you can see what people are looking for. All of this is optional; without a key it searches by words.
- **Live updates.** The ticket list, the folder counts, the open ticket, the tasks board, the open task and the bell now follow everybody's changes - every 15 seconds while the tab is open, and at once when you come back to it. Nothing you are typing, choosing or saving is ever replaced: if a colleague changes the ticket you are writing on, a small "Updated just now · Refresh" appears instead. **Preferences → Live updates** sets the pace, or turns it off. Raised by pappas81.
- **Watch a ticket.** Follow a ticket without owning it: **Watch** on the ticket, or **Watch / Stop watching** from the right-click menu, for one ticket or a whole selection. Watchers are told about replies, notes, status, priority, reassignment and SLA warnings through their own notification preferences, and only while they can see the ticket. **Tickets → Settings → General → Watching tickets** chooses what watchers are told, and what happens to a watcher who is deactivated. Raised by pappas81.
- **Forms on a ticket.** **Tickets → Settings → Checklists → Forms on tickets** puts a **Forms** button on each ticket: add a form, fill it in on the ticket, and make it required before the ticket can close - or just a warning, or optional. Also on the workspace's Work tab and the right-click menu. Off by default; needs the Forms module. Raised by pappas81.
- **Workflows that route tickets by category.** Category is now a condition on every ticket trigger - "a ticket is created in Hardware → assign it to the Desktop team" - and a new trigger, **A ticket's category changes**, catches email tickets that are categorised at triage. A condition on a category also matches its subcategories; **Tickets → Settings → Categories → Categories in workflows** makes it exact instead. Raised by Shadowtech87.
- **Workflows for tasks.** Task triggers know the task's ticket, so a workflow can write on the ticket when its task is done, and three new actions set a task's status, assign it and comment on it. Raised by pappas81.
- **Workflow notes that are real notes.** **Add a note to the ticket** can now write an actual note on the ticket, by System, internal unless you share it with the requester - not only a history entry. Existing workflows keep doing what they did. Raised by pappas81.
- **Save a copy of sent mail, for Basic IMAP mailboxes.** A switch on each Basic IMAP mailbox files a copy of everything it sends in the mailbox's Sent folder, so people reading the mailbox in Thunderbird or webmail see what the service desk sent. Off by default, because Gmail, Microsoft 365 and some hosts already do this themselves. Raised by pappas81.
- **System → Maintenance.** One place for the tools that find data left behind, each card saying how much it has found. Orphaned tickets is the first. Contributed by vsc55.
- **A reply without a ticket number.** **Tickets → Settings → General** can now add an email with no ticket number in its subject to the ticket its email conversation already belongs to, so a requester replying to their own first email to add something no longer opens a duplicate. Raised by Kraleemil.
- **A reminder for an unanswered satisfaction survey.** **Tickets → Settings → CSAT** can send one reminder a set number of hours after a survey goes unanswered. Suggested by Abdullah31H.
- **Requester columns in the ticket table.** **Requester** and **Requester email** can be added from the column chooser - sortable, and in the CSV export. Raised by acelr22.
- **Ticket checklists ask for results.** A checklist step on a ticket can ask for a result - Pass, Fail (with what went wrong) or Not applicable - as task checklists already could, and steps show their description. Right-click a ticket → **Attach checklist** lists the best matches first. Raised by pappas81.
- **Checklists in the REST API.** Read a ticket's or a task's checklists, and tick steps, through the API. Raised by pappas81.
- **Greek.** FreeITSM is now available in Greek (Ελληνικά), complete. **Polish** and **Indonesian** are now complete too, including Starters & leavers, which bbieganski asked for.

## Improvements

- **Back from a full-screen ticket keeps full screen.** Back and Escape return straight to the list, and the next ticket still opens full screen; the shrink icon is the switch. A reply you had started is still there when you go back. Contributed by Dr4inder.
- **Hyper-V virtual machines report their guest OS.** Replace the collector with version 1.0.1 and the Guest OS column fills in, for every VM running integration services. Contributed by Dr4inder.
- **CMDB relationships read correctly in every language**: "VM-A runs on HOST-A", naming both ends. Contributed by Dr4inder.
- **Impact and Risk impact are told apart** on a change, each with a line saying what it is for; only Risk impact and likelihood set the risk score. Contributed by Dr4inder.
- **Software inventory columns say what they count**: Installations and Licence seats. Contributed by Dr4inder.
- **Preference templates can include two more preferences**: empty Work sections on a task, and your company for new tickets. Contributed by Dr4inder.
- **A workflow that skips part of its job says so.** If an action cannot do everything it was asked - a checklist that is for tasks only, say - the run still finishes, the step leaves a note, the run history's **Needs a look** filter finds it, and Watchtower's Workflows card counts it.

## Fixes

- **A change could not be opened with Enforce approvals on** ("Error loading change"). Reported, diagnosed and fixed by tudang85.
- **Comments imported from Jira or Azure DevOps never arrived** on an install created fresh, and were never tried again. Database Verification now frees the stuck ones.
- **The CSAT "Delay before sending" did nothing** - the survey went the moment a ticket closed. It now waits, and a ticket reopened in the meantime gets no survey. Reported by Abdullah31H.
- **Saving a checklist template wiped every step's description.**
- **A long Knowledge article in accented or non-Latin text never got an AI embedding**, so the Knowledge assistant could not find it by meaning.
- **Smaller fixes**: the Jira set-up step "Get a API token"; checklists from the REST API now carry their template version.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**. This release adds tables and columns, and lets a note be written by System with no analyst.
3. Hard-refresh your browser (Ctrl-F5).
4. **If you use the Hyper-V collector**, replace `Invoke-HyperVInventory.ps1` on your management server with the new one (version 1.0.1) to get guest operating systems. The old one keeps working without them.
5. **If you set a CSAT delay**, a new background job sends delayed surveys every five minutes. With the built-in scheduler there is nothing to do; if you run scheduled tasks by hand, add `cron/csat_delayed.php`.

## Rollback

Safe - nothing was removed from the database, so you can go back to 4.12.0. One thing to know if you do: a satisfaction survey still waiting for its delay will not be sent.
