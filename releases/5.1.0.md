## What this release is about

5.1.0 has **six security fixes**, and everyone should upgrade. The most important one: a team's departments now decide which tickets its members can see and open. Before, they only trimmed the department folders. Read the Security section before you upgrade, because some analysts may see fewer tickets afterwards - which is the point.

Beyond that, project budgets can now be kept against your **finance department's chart of accounts**, with income as well as costs. Projects' documents can be added and fetched **through the REST API**, behind new **threat protection** for every API key and an **activity log** of every call. Each mailbox can now put its tickets **in its own department**. Danish, French and Ukrainian are complete again.

## Security

These six were found and fixed on 12 November 2026. All of them are present in every release up to and including 5.0.0. Upgrading is the whole fix; nothing else needs doing.

- **Departments did not limit which tickets an analyst could see.** **Tickets → Settings → Teams** links a team to departments, and that trimmed the department folders - but the **All tickets** list, searches, opening a ticket by its number, linked tickets on changes and problems, Report Packs, Watchtower, the War Room bot and the REST API all ignored it. An analyst in a Facilities team could find and open an HR ticket. Now, an analyst in at least one team sees a ticket when it is in one of their teams' departments, has no department, is theirs, is assigned to one of their teams, or is one they are watching. Administrators, and analysts who are in no team, see everything as before. An API key sees what its analyst sees.
- **A switched-off team still granted access.** Turning a team's **Active** switch off did not take away the modules, companies, roles, and Knowledge, Report Pack and project shares it gave its members. It does now.
- **A text name could run as script in a colleague's browser.** On some lists, a name with an apostrophe in a particular shape ran as script when someone clicked the row's buttons. The worst case was a software title or a hostname reported by a managed device, which the person using that device chooses. Names typed by analysts (teams, departments, article titles and tags, CMDB classes, contracts) could do the same to another analyst.
- **Email templates put the requester's own text into HTML unescaped.** A ticket subject or requester name containing HTML - a link or a fake button - arrived as real HTML in mail sent from the service desk's own address. Every value is now escaped in an HTML template.
- **A CMDB blast radius crossed companies.** On an install with several companies, objects with no company appeared in another company's blast radius.
- **Network Mapper accepted any relationship for a connector**, including one from another company or between unrelated objects. A connector's relationship must now link the two objects it joins.

## New features

- **Chart of accounts.** **System → Chart of Accounts** holds your finance department's accounts for each company - code, name, kind (Expense, Fixed asset, Payroll, Income), parent - imported from Excel or CSV, exported, and kept in step through the REST API. Requested by a supporter of the project.
- **Project budgets by account.** A budget line can name one account or be split across several, by percentage or by amount. Each project has default accounts for its time and its other spending. A project task can say which account its logged time counts against, and the Budget tab ends with **Costs and income by account**, adding up to the planned, actual and forecast figures, exportable to Excel. Also a Report Packs block, and the portfolio's Charts view across projects.
- **Income on projects.** An **Income** panel on a project's Budget tab records what the project brings in - planned and received amounts and dates - and shows income less costs. Income is never added into the budget.
- **A project's documents in the REST API.** Add a file or a link to a project, list its documents, fetch one, link one already in FreeITSM, or remove one. Fetching a file needs its own key permission, **Documents → Download**, which "Select all" never ticks. Proposed by cloudcogsio.
- **API threat protection.** **System → API** has a new **Threat protection** tab. Each key can be limited to certain addresses and certain hours, and given its own download limits. Across the install, FreeITSM alerts administrators by bell and email - and can stop the key - when a key downloads too much in an hour, is refused again and again (probing), or is used from a new address. An address that keeps sending bad keys is blocked for a while. Every alert and refusal is logged on the tab.
- **Keys that act as an administrator.** A Threat protection setting allows them with a warning (the default), allows them only with allowed addresses, or forbids them. It is checked on every call, so an analyst made an administrator later is caught.
- **API activity log.** **System → API → Activity** lists every REST and MCP call - which key, what it asked for, whether it worked, how long it took, from where - never the contents. Kept for 30 days by default, then deleted or zipped (a zip per day, week or month) by a new background job.
- **A department per mailbox.** **Tickets → Settings → Mailboxes → Department** puts new emailed tickets from that mailbox in a department of your choice. Left blank, nothing changes. Raised in a user's email.

## Improvements

- **Ask AI buttons show only when they can work** - in Knowledge, on a ticket, in the Projects assistant and in CMDB - instead of appearing and then failing because that feature's AI was not set up.
- **Danish, French and Ukrainian are complete again**, and Spanish, German, Polish, Greek and Indonesian are complete with everything in this release.
- **CMDB relationships read the right way round** in the AI summary and in Network Mapper ("VM-A runs on HOST-A"), as they already did on the object page.
- **Workflows routing by category**: changing a ticket's type, which clears its category, now fires **A ticket's category changes**, and the Old and New category conditions are pick-lists rather than number boxes.
- **The REST API's list of workflow actions** says which choices each setting accepts.

## Fixes

- **Time logged on a project task's subtasks never reached the project's budget.**
- **Undo merge lost a watcher, CMDB object, asset, problem, change or form that was on both tickets.** Merges made from now on undo completely; older merges cannot get them back.
- **A form's actions did not save what the editor showed** - a new **Add a note** action saved as a history entry only, and a Ticket ID box showing `{{ticket.id}}` saved nothing.
- **A ticket closed without a closed date** (by an import, say) kept its SLA resolution clock running.
- **Smaller fixes**: calendar feeds could split an accented letter or an emoji in two; renaming a War Room channel to nothing looked as though it had saved; a SCORM 1.2 course got the wrong error code for a read-only value; two chart-of-accounts settings showed an empty "Default:" and a raw "all".

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**. This release adds tables and columns.
3. Hard-refresh your browser (Ctrl-F5).
4. **Check your teams' departments.** If your analysts are in teams, they now see only their teams' departments' tickets (plus their own, their teams', ones they watch, and ones with no department). If someone can no longer see tickets they should, add that department to their team under **Tickets → Settings → Teams**.
5. **API activity log tidy-up**: with the built-in scheduler there is nothing to do. If you run scheduled tasks by hand, add `cron/api_log_tidy.php` once a day.

## Rollback

Safe - this release only adds to the database, so you can go back to 5.0.0. Going back also brings back the six security issues above.
