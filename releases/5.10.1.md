## What this release is about

FreeITSM carries its own copies of the libraries it is built on, so nothing has to be downloaded when it runs. This release brings every one of them up to its latest version, all on the same day. Most of what you will notice is small: charts, PDFs and the editor look and behave as before. The one visible change is a fix - a QR code on an asset label can now hold a name like *Łódź laptop* or *Ноутбук* and still be read.

## Improvements

- **The rich text editor, charts, PDF making and PDF viewing are on their latest versions.** TinyMCE 8.10.2 (bug fixes such as the image dialog sticking on "Uploading image" with an unreadable file), Chart.js 4.6.1, PDFKit 0.21.0 and pdf.js 6.5.438. Domains and Morning Checks used an older copy of Chart.js of their own; every chart now uses the same one.
- **Single sign-on and Teams messages are checked by php-jwt 7.2.2**, which refuses signing keys that are too short to be safe. Microsoft Entra, Google, Okta and the other usual sign-in providers use keys well above the minimum, so nothing changes for them.
- **The list of trusted certificate authorities FreeITSM ships is Mozilla's latest** (5 November 2026). It is used for outgoing connections - email, Microsoft 365, AI providers, domain checks - on servers whose PHP has no certificate list of its own.
- **QR codes are made by qrcode-generator 2.0.4.** Codes with plain text come out exactly as before, so nothing printed needs printing again.

## Fixes

- **A QR code holding accented or non-Latin text came out wrong.** Polish, Russian or Hindi turned into the wrong characters, and FreeITSM's own scanner could not read an accented name at all. QR codes now store text as UTF-8. Labels printed before this release stay as they were.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Hard-refresh your browser (Ctrl-F5) - this release updates cached JavaScript. No Database Verification is needed.

If you sign in through your own identity provider with a signing key shorter than 2048 bits - very unusual - single sign-on will refuse its tokens after upgrading. Give the provider a 2048-bit (or longer) key.

## Rollback

Safe - nothing changed in the database, so you can go back to 5.10.0.
