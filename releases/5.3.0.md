## What this release is about

**Fixes a problem in 5.2.0:** opening a file from the **Files** desktop failed with *"Cannot read properties of null (reading 'open')"*, on every install and every kind of storage. If you are on 5.2.0, upgrade.

The CMDB gets the biggest step since it arrived: **Starter classes** set up a sensible CMDB in one click, and the new **CMDB assistant** asks about your organisation, remembers what it learns for each company, and suggests the classes and then the configuration items themselves - you see a preview and apply it. Configuration items can point at the **real people, teams and locations** FreeITSM already holds. Each company can have **its own priorities and SLA hours**, a directory source can be deleted **without leaving a mess behind**, and Intune keeps assets with the right person, of the right type, on its own schedule. Nothing is removed; run Database Verification.

## Security

- **The Intune tab of an asset did not check the asset's company.** On a multi-company install, an analyst limited to some companies could read the Intune device details (device name, user principal name) of an asset in a company they cannot reach, by its number. It now checks the company, as the asset's other tabs do. Affects every release before 5.3.0; upgrading is all that is needed.

## New features

- **CMDB assistant.** An **Assistant** button in the CMDB (once its AI is set up) opens a panel that interviews you about your organisation - your services, what they run on, what you want the CMDB to answer - and notes what matters. Your conversation is your own; what it learns is kept for each company and shared by everyone who works on that company's CMDB, under **Learned**, where you can correct or forget it. When it knows enough it suggests **classes and properties**, then the **configuration items** you told it about; each suggestion opens in a preview where you untick what you do not want, and **Apply** adds the rest in one go.
- **Starter classes.** CMDB → Settings → Classes has a **Starter classes** button: nine common classes - Service, Application, Server, Virtual machine, Database, Network device, Laptop / desktop, Mobile device, Subscription - with a handful of properties each, previewed first; only what is missing is added. A new guide, *Designing your CMDB*, explains what belongs where.
- **CMDB properties that point at real records.** A property can be a **Person, Analyst, Team, Location, Company, Supplier or Contract**, showing the record's current name with a link - no more copies kept by hand. The CMDB list can be **filtered by any property** with up to three property columns, and deleting a person, team or location that configuration items name tells you which ones first.
- **Priorities and SLA hours for each company.** Beside the shared ones, a company can have its own priorities, SLA targets and business hours, and every place a ticket is raised - email, portal, chat, Teams, catalogue, monitoring, workflows, the API - follows the ticket's company.
- **Imported people, and "what if" before deleting a directory source.** A person is managed by an LDAP, CardDAV or Entra source only while that source exists. Deleting a source first shows everything it would affect - the people it imported, their sign-in links, group mappings - and asks whether to keep them or mark them as leavers. **System → Maintenance → Imported people** lists people whose source was deleted, people a source no longer brings in, and can remove the people an import created (never the ones that were already here).
- **Emailed reports.** A report like that preview can be emailed to yourself - in the body, as an attachment (for installs nothing outside can reach), as a download link, or any mix, chosen under **System → Emailed reports**. Links open only for the person they were sent to, after signing in, expire, can be revoked, and every download is logged.
- **System → Locations, and a Location question in Forms.** Your sites, buildings, floors and rooms as one tree for each company, with locations every company can share; a form can ask *"Which office are you in?"* and get a real location.
- **Companies: outside reference, tax ID and the REST API.** Each company can carry its ERP or CRM ID and VAT number, System → Companies has a search, and the API can create, update and **upsert companies by outside reference** - an ERP can send its customer list every night without making duplicates.
- **Intune: assets follow their primary user.** Every primary user a device has had is kept on the asset's Intune tab. With **Follow changes of primary user** on, an asset Intune gave to somebody moves to the new primary user - a holder chosen by a person is never moved - and System → Maintenance lists the assets whose Intune user differs, to decide by hand.
- **Intune: each asset gets a type** from what the device is - laptop, desktop, server, phone, tablet - mapped to your own asset types, with suggestions. A type somebody chose is never changed.
- **Intune syncs run on their own.** Devices every 6 hours and software daily, as background jobs, carrying on where they stopped; the Intune tab says when each last ran.
- **Background jobs: Run now.** Start any job straight away to check a fix, and see who started each run.

## Improvements

- **Assets reach their Intune primary user after an Entra import too**, not only after the next Intune sync.
- **The asset list can be grouped by type**, each group folding away.
- **The System page shows its cards by topic**, with a heading for each group, or A to Z.
- **Every System screen uses the full width, and every System dialog looks and works the same.**
- **Mail from a person you already know reaches their company**, without adding them as a specific sender.
- **A ticket note's files open in the preview** like the ticket's other attachments.
- **The project assistant works with an AI server that needs no key.**
- **Danish, German, Greek, Spanish, French, Indonesian, Polish and Ukrainian** have everything in this release.

## Fixes

- **Opening a file on the Files desktop failed** - since 5.2.0, on every install. Fixed.
- **Reporting → Intune showed only an error** on some database servers once there were Intune devices.
- **Deleting a directory source left its people locked** - their job title, department, phones and manager could never be edited again.
- **Webhooks: View on a delivery opened nothing.**
- **Importing cost centres or accounts showed the Back and Import buttons on the first step.**
- **Saving a CMDB property from the cog switched off "This is a dependency".**
- **About twenty System pages ran a little past the bottom of the window.**

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**. It adds the tables for the CMDB assistant, Intune history and emailed-report links, and columns for record properties, company references, per-company priorities and asset sources.
3. Hard-refresh your browser (Ctrl-F5).
4. If you use the built-in scheduler, the two Intune syncs start running on their own once Intune is set up - change or switch them off under **Reporting → Background jobs**.

## Rollback

Safe - this release only adds to the database, so you can go back to 5.2.0.
