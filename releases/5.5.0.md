## What this release is about

A release built almost entirely from your requests and reports - thank you to everyone who sent them. Projects can now move to another company, portal users can pick their own language, form lookups can ask "which company?", and you can have each module reopen where you left it. If you use the **REST API** to manage tasks, or to set the times on changes or tickets, read the Security section and the note under Fixes before upgrading.

## Security

- **An API key limited to some companies could reach other companies' work through tasks.** Through the REST API, such a key could link a new task to a change in another company, create a subtask under another company's task (putting the new task in that company), and tell from the reply whether a change number existed. The screens were not affected. Present in every version up to 5.4.1; upgrading is all that is needed ([#371](https://github.com/edmozley/freeitsm/issues/371), reported and fixed by @cloudcogsio).

## New features

- **Move a project to another company.** **Move** on a project's page takes the project, its tasks and their subtasks to another company in one go. If the project manager or anyone on the team could not see the new company, or a task is linked to another company's ticket or change, it says so and moves nothing - nobody is taken off a project for you. Also in the REST API ([#370](https://github.com/edmozley/freeitsm/issues/370)).
- **Portal users choose their language.** In the self-service portal, **My account → Language** lists every language FreeITSM ships; the default is still the browser's language ([#368](https://github.com/edmozley/freeitsm/issues/368)).
- **Form lookups can ask "which company?"** A lookup question can now search your **Companies**, offering only the companies the person filling it in can reach. And a **People** lookup now finds someone by employee ID, job title, department, phone number or any of their custom fields, not just name and email ([#367](https://github.com/edmozley/freeitsm/issues/367)).
- **Reopen the last section of each module.** Switch it on in **Preferences** and opening a module from the menu, the sidebar, the home page or Ctrl+K takes you back to the section you last used there - Assets → Servers, say - instead of its front page. Off unless you switch it on ([#376](https://github.com/edmozley/freeitsm/issues/376)).
- **The REST API shows and filters a task's company**, and can create a task in a chosen company, as it already could for tickets and projects ([#371](https://github.com/edmozley/freeitsm/issues/371)).

## Improvements

- **Module colours now reach the whole module.** A colour set in **System → Module colours** drives that module's buttons, links, tabs and highlights, in light and dark, not just its header ([#302](https://github.com/edmozley/freeitsm/issues/302)).
- **The ticket's button row stays still** when you move from one ticket to the next, instead of the buttons jumping about while the ticket loads.
- **Under All companies, Change Management shows every company you can reach** - the list and the calendar - with each change's company on its card, and so do Watchtower's Domains and Projects cards. CMDB and Starters & leavers still show one company at a time, and now say which ([#373](https://github.com/edmozley/freeitsm/issues/373)).

## Fixes

- **⚠️ For REST API users: change and ticket times are now plain local times.** The work, outage and review times of a change and a ticket's scheduled work are shown in FreeITSM exactly as typed, but the API treated them as UTC, so a time sent with a time zone landed at the wrong hour - sometimes on the wrong day. The API now stores and returns them exactly as sent, without a `Z`, and **refuses a time that carries a time zone**. If your integration sends these times with a `Z` or an offset, send the local time instead before you upgrade ([#375](https://github.com/edmozley/freeitsm/issues/375)).
- **The calendar popup ran off the bottom of the screen** for events low on the page, hiding its Edit button, in the Calendar and the Change calendar ([#374](https://github.com/edmozley/freeitsm/issues/374)).
- **Under All companies, Change Management showed only the company picked last**, with nothing to say so ([#373](https://github.com/edmozley/freeitsm/issues/373)).
- **The asset handover preview and email were always in English**, whatever the analyst's language (thanks @Dr4inder).
- **The Domains certificate check could fail** on a certificate with more than one common name (thanks @Dr4inder).
- **The Domains CSV import showed a code instead of the Scope label** (thanks @Dr4inder).

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**.
3. Hard-refresh your browser (Ctrl-F5).

If you have integrations using the REST API, check the note on change and ticket times above first.

## Rollback

Safe - nothing was added to or removed from the database, so you can go back to 5.4.1.
