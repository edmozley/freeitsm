## What this release is about

The biggest addition is for anyone who automates FreeITSM: **System → API → Scripts** is a library of ready-made, heavily commented PowerShell and Python scripts for real jobs - exporting tickets, turning alerts into tickets, syncing people, importing assets, migrating a knowledge base. Alongside it, the REST API can now bring a whole knowledge base in from another tool, with its folders, pictures and permissions. Knowledge drafts written by the AI finally show as drafts and can be published, the Reply Cleanup prompt can be edited with every version kept, and Basic IMAP mailboxes can send through relays that trust your server instead of a login.

## New features

- **System → API → Scripts.** A searchable library of scripts that use the REST API, each in **PowerShell and Python**, filterable by module, by "read only" or "changes data", and by level. Each one lists the endpoints it calls and the exact permissions its key needs, and comes with **Copy** and **Download**. Scripts that change data only show what they would do until you add `-Apply` / `--apply`, and the Python ones need nothing installed. They ship with FreeITSM as files and run on your own computer - never on the server, and never stored where anything inside FreeITSM could change them. Start with **Check your API key**.
- **Move a whole knowledge base into FreeITSM through the REST API.** Folders, articles, access lists and the pictures inside articles can be created by a script, and a restricted article is restricted from the moment it arrives. Every create can be safely repeated, so an interrupted migration just runs again without making duplicates, and an update is refused if somebody edited the article in the meantime. Pictures are stored securely and checked against the article's permissions every time they are shown ([#377](https://github.com/edmozley/freeitsm/issues/377), built by @Dr4inder).
- **Your own Reply Cleanup prompt, with a history.** **Tickets → Settings → Reply Cleanup** now lets you edit the prompt the AI is sent. Every saved version is kept under **History**: **Restore** puts an earlier one back and **Reset** returns to the built-in prompt, so a change that makes things worse is one click from being undone ([#396](https://github.com/edmozley/freeitsm/issues/396), thanks @pappas81).
- **Send through a mail relay that does not want a login.** A Basic IMAP mailbox has a new **Authenticate with the SMTP server** switch. Turn it off for an internal relay that trusts your server by its address; it stays on for every existing mailbox (built by @Dr4inder).
- **Net or gross purchase costs.** An asset's purchase cost now says whether it includes tax: **Net (excl. tax)**, **Gross (incl. tax)** or **Not specified**, chosen under the amount on the **Financial** tab. It travels with the cost into the asset table and its export, imports and the REST API, and changing it never changes the amount. Costs entered before this release show Not specified until you pick one ([#403](https://github.com/edmozley/freeitsm/issues/403), thanks @Dr4inder).
- **Move a domain to another company.** **Move** on a domain's page takes it, its internal view and its subdomains to another company in one go, and says why if it cannot - also available in the REST API ([#384](https://github.com/edmozley/freeitsm/issues/384), built by @cloudcogsio).

## Improvements

- **The AI summary, "Read this ticket for me" and the merge briefing are written in your language**, headings included, instead of always in English ([#396](https://github.com/edmozley/freeitsm/issues/396)).
- **The people in a ticket's header are links.** From, Requester, To and CC open that person on **Tickets → Users** in a new tab ([#397](https://github.com/edmozley/freeitsm/issues/397), thanks @pappas81).
- **New on the People, Companies and Suppliers lists**, opening the screen that creates each one with its Add dialog ready ([#397](https://github.com/edmozley/freeitsm/issues/397), thanks @pappas81).
- **AI features say "the AI", not "Claude"**, wherever you can choose any provider - including the Knowledge chat, which said "Powered by Claude Haiku" whatever model was set ([#396](https://github.com/edmozley/freeitsm/issues/396)).

## Fixes

- **The REST API ignored asset tags.** A tag could be set on a new asset but never read back or searched for, and changing one was silently ignored. Assets now return their tag, can be found by it, and a change is saved - or refused if another asset already has that tag.
- **AI-written knowledge drafts looked like published articles and could not be published.** Drafts now carry a **Draft** badge and a **Publish** button; until then only analysts can see them.
- **Renaming a change priority, type or impact broke saving a change** with "Unknown priority". The change editor now uses your configured lists (thanks @Dr4inder).
- **Right-click flyouts on a ticket ran off the bottom of the window**, so their last entries could not be reached ([#395](https://github.com/edmozley/freeitsm/issues/395), reported and fixed by @cloudcogsio).
- **Clicking beside a switch in Preferences flipped it** - anywhere on its row, even empty space. Only the switch itself does now (thanks @Dr4inder).
- **Asset labels left Company blank** for assets in the default company (thanks @Dr4inder).

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification** - it adds the tables for the Reply Cleanup history and Knowledge pictures, the mailbox relay setting and the net / gross purchase cost.
3. Hard-refresh your browser (Ctrl-F5).
4. **nginx only:** if you maintain your own config rather than the one in `deploy/nginx/`, add `location ^~ /script-library/ { return 404; }` (Apache and IIS are covered by files that ship with the release).

## Rollback

Safe to go back to 5.6.0: everything added to the database is new tables and new columns, which 5.6.0 ignores. Two things to know: a mailbox with authentication turned off will try to log in to its relay again, and edited Reply Cleanup prompts go back to the built-in one (they stay saved, ready for when you upgrade again).
